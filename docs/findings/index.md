# Findings

The study asks one question — **which benchmarks give a reliable signal at
each stage of multilingual training?** — in the order a developer asks it.
Is a benchmark's score **above chance** at the size and number of training
tokens a proxy can afford (RQ0, RQ1)? Does a smaller or earlier model **rank
the design choices** like the fully trained 1.7B reference (RQ2, RQ5)? Can
that be told **from the proxy alone**, through noise and signal-to-noise
statistics (RQ3, RQ4)? The other questions test how far the answers
generalise and how benchmarks could be improved. Each page states the
question, how we measure it on the [ladder](../ladder.md), interactive views
of the results and what to take from it.

## The research questions

| theme | RQ | question | in short |
|---|---|---|---|
| A · Is the evaluation predictable? | [RQ0](gate.md) | Which benchmarks are above chance, in which language, from which model size and how many tokens of the language? | In trained languages, 40 % of the tasks pass at 90M and 64 % at 1.7B; scoring the answer text instead of a letter moves whole benchmarks across the threshold. |
| | [RQ1](scaling.md) | Which scores move with model size and training in a way a trend line captures? | Above chance, accuracy scales log-linearly (median R² 0.87); per-language bits per byte fits almost perfectly. |
| | [RQ2](decision-accuracy.md) | Does a small model, or an early checkpoint, rank training choices like the 1.7B model? | On benchmark accuracy a smaller model agrees on 51–56 % of decisions; on per-language bits per byte on 89–94 % (except 600M). Training the proxy longer does not close the gap. |
| B · Can it be measured cheaply? | [RQ3](noise-snr.md) | How much does a score move by chance, and how large is a real difference against that noise (SNR)? | Seed noise is 1.75× the checkpoint noise, and no design decision clears 2× the seed noise in half its cells. |
| | [RQ4](surrogates.md) | Which statistic, computed on the small model alone, predicts that it ranks correctly? | Early-checkpoint agreement and the relative-spread SNR lead at ρ ≈ 0.6, from 90M; signal alone carries nothing. |
| C · Does it generalise? | [RQ5](design-decisions.md) | For each training choice, which proxy sizes read it correctly, and how early? | Bits per byte reads the temperature and language-list decisions from 90M. On the benchmarks, every decision but the two swaps of the English corpus sits at 0.45–0.63. |
| | [RQ6](language-transfer.md) | Does what we learn transfer to languages we did not measure, or never trained on? | One 175M measurement predicts a language's 1.7B bits per byte within 4.4 % (5.0 % if never trained). |
| | [RQ7](external.md) | Do our SNR values agree with AllenAI's DataDecide on English? | The nine shared English tasks rank alike (ρ 0.78), but our SNR levels are lower, so only the order compares. |
| D · Can benchmarks be improved? | [RQ8](subsets.md) | Can a subset of a benchmark beat the full set? | A chosen language subset beats a random one in 77 of 98 testable cells; picking items by SNR loses the reference ranking. |
| | [RQ9](benchmark-design.md) | Which design features make a benchmark reliable? | The option count orders the families by SNR, but only item count and skill order them by DA-size. |
| | [RQ12](above-chance-items.md) | Do the scores get more reliable if we keep only the questions the 1.7B model answers above chance? | SNR rises (mostly through lower noise), decision accuracy barely moves. |
| E · Past the reference | [RQ10](size-generalisation.md) | Does a ranking that holds at 1.7B still hold at 3B? | Accuracy ranks the 3B runs at chance from every proxy; bits per byte at 0.78–0.95. |
| F · The recommendation | [RQ11](recipe.md) | Which benchmark, posed and scored how, gives a reliable decision from the smallest model? | None reaches a 0.75 bar on average by 1B; the best (LLM-reformulated, scored by bits per byte) reads 0.62. |
| Sanity check | [RQ13](english-only.md) | Do the English-only models do better on English benchmarks, as they should? | Yes, by a small margin (1.1 points at 1.7B), and they always have the lower English bits per byte. |

The model ladder behind every page has 218 runs (90M–3B, 1 to 50 training
languages, depth, activation, optimizer and data interventions, seed
replicates); the analyses read 90M–1.7B against the 1.7B reference, and RQ10
the six 3B runs. Every number on these pages comes from the committed
analysis tables under `src/signal-and-noise/analysis/`, regenerated by
`scripts/refresh_analysis.sh`; the "What we find" blocks are quoted from the
RQ READMEs at build time, and the short answers above summarise the
2026-10-10 refresh.
