## 1. Checkpoint density for the reference models

**Today (commit 8642261):** 20 evenly spaced checkpoints per run, 40 at 1.7B; every
size saves at k/20 of training, 1×C is checkpoint 4 (8 of 40), final on-grid.
**Proposal:** 20 for ≤600M, **40 for 1B, 60 for 1.7B**.

A priori we evaluate ~20 points per run (every 2nd checkpoint) plus the last 5.
Extra saved checkpoints are optionality: they can be evaluated later; missing ones
can never be recovered. The reference models (1B/1.7B) anchor every
decision-accuracy comparison and every FLOPs-matched read, so density pays most there.

## 2. Comparison axis: same fraction of training vs same FLOPs

With D = 100·N per size, a checkpoint at fraction *f* of a run sits at tokens
100·N·f and FLOPs ≈ 6·N_eff·100·N·f ∝ N². So "same % of training" is "same
multiple of Chinchilla" (ckpt 4 = 1×C, 8 = 2×C, …, 20 = 5×C) — **not** the same
tokens and **not** the same compute. Equal-FLOPs pairs across sizes only exist
where the runs overlap:

| Smaller run's *final* FLOPs equals the larger run at … | 175M | 350M | 600M | 1B | 1.7B |
|---|---|---|---|---|---|
| 90M final (1.1e19) | 33 % | 10 % | 3.8 % | 1.6 % (iter 739) | 0.5 % (iter 441) |
| 175M final (3.3e19) | — | 31 % | 12 % | 4.9 % | 1.7 % |
| 350M final (1.1e20) | — | — | 37 % | 16 % | 5.3 % |
| 600M final (2.8e20) | — | — | — | 43 % | 14 % |
| 1B final (6.7e20) | — | — | — | — | 34 % |

FLOPs = 6·(N_non-emb + d·V)·D, the compute-budget convention. Below ~4 % of a run the large model is still in LR warmup (4 % of iters), so equal-FLOPs comparisons between far-apart sizes compare a finished small model with a warming-up large one — not a decision-relevant pairing.

| Axis | What it answers | Who uses it | Needs a dedicated save grid? |
|---|---|---|---|
| Same ×C (fraction of own budget) — **what we save on** | "Does a proxy trained to its budget rank interventions like the reference trained to its budget?" — decision accuracy at equal compute-*optimality* | Signal-and-Noise, DataDecide, the Bhagia ladder | Yes — ours delivers exact index pairs at every size |
| Same FLOPs | "At compute X, which size/shape predicts best?"; IsoFLOP-style scaling fits; comparability with external models | Chinchilla-style fits; our W&B charts already default to x = FLOPs | No — any checkpoint has a known (N, D); pairs come from interpolation along each model's curve (BPB is smooth) or the nearest checkpoint |
| Same tokens | "How much data" questions | Rarely the right axis here: tokens are confounded with size by design | No |

| Option | Pros | Cons |
|---|---|---|
| **Keep the relative grid for saving; report both axes in analysis** | Exact cross-size pairs for decision accuracy; 1×C and final on-grid; FLOPs view costs nothing extra (interpolate / nearest ckpt — with 1-B the nearest-ckpt error at 1B/1.7B is ≤ 1.25 % / 0.8 % of a run); external models slot into the FLOPs view as today | FLOPs-matched pairs are interpolated rather than saved points |
| Save on FLOP milestones instead (e.g. 1e19, 3e19, 1e20, 3e20, 1e21) | Exact equal-FLOPs checkpoints | Milestones fall in warmup for the big sizes and past the budget for the small ones — only adjacent sizes share more than 2–3; 1×C/final go off-grid; the per-size decision-accuracy grid is lost |
| Both grids | Exact pairs on both axes | More checkpoints and a second schedule, for points interpolation already gives to < 1 % |

**Recommendation:** keep saving on the relative grid; report *both* decision
accuracy at matched ×C **and** curves vs FLOPs; add FLOP milestones to the *eval*
due-rule (evaluate the nearest checkpoint to each milestone) if exact evaluated
points are wanted. Fix one FLOPs convention now and apply it to external models
too: recommend **6·(N_non-emb + d·V)·D** (the embedding lookup is free, the output
projection is not — with a 131K vocab it nearly doubles the small models' compute);
the W&B push currently uses total parameters, so align it.

**Decision to record:** FLOPs convention = ___ ; milestone evals: yes / no.

## 3. Grid size and budget (review finding 3)

The code trains **56 runs per level** (×3 seeds at 175M/1B for L ∈ {1, 2, 30, 100};
1.7B at L ∈ {1, 2, 8, 30, 100}) — the L2 additions of 2026-08-19. The budget of

fast-mix **≈ $130k** (headroom ≈ $70k of the $200k grant), ~145 concurrent H100s

## 5. Shallow ladder — confirm the committed design (finding 7, commit 2f69d74)

The depth intervention compares deep (width/depth ≈ 64) vs shallow at equal
non-embedding size. The old shallow ladder let the search pick FFN multiplier
(4,6,6,4,6,4) and GQA ratio (2,3,2,3,4,2) per size, while deep uses 4/4 uniformly —
so "depth" also changed FFN share and KV heads. Now: ffw = 4 and gqa = 4 pinned,
d_model a multiple of 256, width/depth in [96, 160], best-N within 4 % then ratio
closest to 128.

| | 90M | 175M | 350M | 600M | 1B | 1.7B |
|---|---|---|---|---|---|---|
| Deep (layers × d, ratio) | 15×768 (51) | 16×1024 (64) | 20×1280 (64) | 24×1536 (64) | 28×1792 (64) | 30×2304 (77) |
| Shallow — old | 8×1024 (128) | 9×1152 (128) | 11×1408 (128) | 15×1920 (128) | 16×2048 (128) | 21×2688 (128) |
| **Shallow — new** | 8×1024 (128) | 10×1280 (128) | 14×1536 (110) | 14×2048 (146) | 17×2304 (136) | 20×2816 (141) |
| N vs deep target | −5.2 % | −2.3 % | +0.8 % | +3.7 % | +0.4 % | −0.4 % |
| Ratio contrast vs deep | 2.5× | 2.0× | 1.7× | 2.3× | 2.1× | 1.8× |

| Option | Pros | Cons |
|---|---|---|
| **A — pinned ffw/gqa, ratio window (committed)** | Layer structure identical to deep → the intervention is aspect ratio only; N within ±5 %; contrast ≥ 1.7× at every size | Ratio varies 110–146 across sizes (not a constant 128); 90M is 5 % under target |
| B — old free search, exact 128 | Constant ratio; N within ±5 % | Confounded: FFN share and KV-head count vary with size and differ from deep |
| C — pinned and exact d = 128·L | Cleanest statement | N moves in ~L³ steps: misses targets by up to 20 % — "same size" no longer holds |
| D — pin ffw only, gqa free | Finer N matching than C | KV-head count still a (minor) confound |

**Recommendation: confirm A**; report results against actual N (the ±5 % is far
below the 2× size steps). Not for today unless there is time: the **third
intervention level** (tokenizer V1 vs V2 vs alternative, or sampling temperature)
is still open — plan question 4.

**Decision to record:** shallow ladder = A / other; third level: ___.
