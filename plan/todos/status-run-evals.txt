RE-EVALUATE THE PRE-WORKER-POOL BACKLOG                          2026-09-08

WHY
  The 2026-09-04 worker pool changed scores. Measured on
  lm-175M-L50-deep-seed1904-iter3416 — three full 329-task runs, 4776
  accuracy metrics each:

      same settings twice (the floor)       0.5 % of metrics move, max 0.0020
      caching on vs off                     0.7 %,                 max 0.0080
      old batched vs new worker + caching    3.5 %,                max 0.0200
      old batched vs new worker, no caching  3.4 %,                max 0.0200

  The shift is the WORKER POOL, not enable_prefix_caching: turning the flag
  off does not close the gap (3.5 % vs 3.4 %). It is systematic and
  time-correlated — every checkpoint evaluated before 2026-09-04 sits on a
  slightly different scale from everything after. The SNR noise estimate is
  taken over 5 late checkpoints, which is exactly where an early-vs-late
  offset is read as noise. Re-run before the fit, not after.

WHAT COUNTS AS STALE
  An eval dir carries job.json iff the worker pool produced it. A task is
  stale when its only result comes from a dir without one. `apertus-*` cells
  are excluded: that sweep is finished and frozen.

  This set only SHRINKS — every eval from 2026-09-04 on uses the worker pool,
  so nothing new becomes stale. When the list below is empty, delete this file.

COST
  353 checkpoints, 29209 stale tasks.

    cold start   353 jobs x 212 s     = 20.8 node-h   (one per checkpoint)
    the tasks    29209 x 6.63 s       = 53.8 node-h
                                      ~= 75 node-hours

  6.63 s/task is the marginal cost measured on the only three FULL 329-task
  worker runs (2303 / 2405 / 2468 s, cold start removed). Do NOT price this
  off `eval_minutes()` (292 node-h — that is the walltime requested, not
  burned) and do NOT apply the 0.05 actual/requested ratio seen on top-ups:
  that ratio is an artefact of the 15-min OVERHEAD_MIN floor on small jobs
  and understates a full re-run by ~5x.

OPEN QUESTION — HOW TO RE-RUN  (decide this first)
  The per-task gate skips anything with a result on disk, so resubmitting
  into `msnr` evaluates NOTHING. Three options:

    a) fresh WANDB_PROJECT (msnr-v2). Reversible, deletes nothing, and
       progress is just `ls <logs>/msnr-v2 | wc -l` against 353. Cost: the
       results tree splits and every reader needs repointing.
    b) move the stale eval_*/ dirs aside. Needs an explicit decision — this
       repo never relocates eval results without one.
    c) add --force to scripts/_eval_status.py. Least disruptive long-term,
       but the gate is what stops runaway resubmission, so tread carefully.

  (a) is the recommended start.

  import json, re, sys, collections
  from pathlib import Path
  sys.path.insert(0, "src/pretrain")
  import auto_evals_cscs as A
  L = Path(A.DEFAULT_LOGS_ROOT) / A.WANDB_ENTITY / A.PROJECT_NAME
  rows = []
  for nd in sorted(L.iterdir()):
      h = nd / "harness"
      if not nd.is_dir() or not h.is_dir() or not nd.name.startswith("lm-"):
          continue
      old = new = 0; ot, nt = set(), set()
      for d in sorted(h.glob("eval_*")):
          if not d.is_dir():
              continue
          tasks = {p.name for p in d.glob("per_task/*") if p.is_dir()}
          for f in d.glob("results_*.json"):
              try: r = json.loads(f.read_text())
              except (OSError, json.JSONDecodeError): continue
              sub = set().union(*[set(v) for v in (r.get("group_subtasks") or {}).values()]) \

              tasks |= set(r.get("results") or {}) - sub
          if (d / "job.json").is_file(): new += 1; nt |= tasks
          else:                          old += 1; ot |= tasks
      if ot - nt:

          rows.append((nd.name, m.group(1) if m else "?", len(ot - nt), old, new))
  rows.sort(key=lambda r: (r[1], r[0]))
  by = collections.Counter()
  for r in rows: by[r[1]] += r[2]
  print(f"{len(rows)} checkpoints, {sum(r[2] for r in rows)} stale tasks")
  print("by size: " + "  ".join(f"{k} {v}" for k, v in sorted(by.items())))

  for n, s, t, o, w in rows:
      print(f"{n:<45}{s:>6}{t:>7}{o:>5}{w:>5}")
  EOF
