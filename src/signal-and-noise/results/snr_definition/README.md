This directory holds per-task SNR/DA tables and the SNR-vs-DA correlation
plots, generated by:

- [`multilingual/run_apertus_snr_variants.py`](../../multilingual/run_apertus_snr_variants.py) — writes `snr_variants_per_task.csv`

## Methodology — what changed

We now have **3 training seeds per (size, mix)** for Apertus: `seed28`,
`seed1797`, `seed1904`. Each (mix, seed) is a separate training run,
giving up to **9 model units per size** (3 mixes × 3 seeds). Plus
reference HF models at 3B/7B/8B/70B feed into the same per-size signal
pool when their size matches an Apertus size (none do yet — Qwen3-0.6B
and Apertus-v1.5-1B are planned).

Each pipeline now accepts a `--seeds` flag. Outputs are partitioned
into `seeds_<a>_<b>_.../` subfolders so multiple seed pools coexist.

**Train / test split for framework generalization.** We "train" on
seeds `{28, 1797}` to find the best SNR variant per language, then
"test" whether the same variant generalizes to the held-out
`{1904}` pool. Results live under `seeds_28_1797__vs__seeds_1904/`.

We also have a **pooled `{28, 1797, 1904}`** run that uses every seed
simultaneously (9 model_families per size) — this gives the highest
statistical power and is the recommended pool for downstream
benchmark-selection work (allenai_comparison, benchmark_creation).

| Pool | Apertus runs | model_families per size | Typical ckpts |
|---|---|---|---|
| `seeds_28_1797` (train) | seed28 + seed1797 × 3 mixes × 4 sizes | 6 | 10–16 |
| `seeds_1904` (test) | seed1904 × 3 mixes × 4 sizes | 3 | 13 |
| `seeds_28_1797_1904` (pooled) | all 3 seeds × 3 mixes × 4 sizes | 9 | 10–16 |

**`model_family` is the cross-size identity** — the model name with
only the size token stripped (so `apertus-175M-fwEdu30-fw270-seed28`
and `apertus-1B-fwEdu30-fw270-seed28` collapse to the same family for
DA-size, but the seed is preserved as part of the family ID — two
different seeds at the same (mix, size) are different families). This
makes the framework seed-agnostic at the API level: any external HF
model (Qwen3-0.6B, Apertus-v1.5-1B, etc.) participates in the SNR
signal pool by `model` and contributes to DA via `model_family` when
its base release exists at multiple sizes.

The headline numbers in this README are **from the
`seeds_28_1797` (train) split** — that's the corpus we use to pick
the recommended variant per language. The
`seeds_28_1797__vs__seeds_1904/` summary checks whether those picks
hold on the held-out seed.

## Framework generalization — does this generalize to seed=1904?

See [`seeds_28_1797__vs__seeds_1904/summary.md`](seeds_28_1797__vs__seeds_1904/summary.md).

|  | DA-size | DA-ckpt |
|---|---:|---:|
| Exact-variant agreement (lang-level) | **7% (1/14)** | **7% (1/14)** |
| Family-level agreement (lang-level) | 14% (2/14) | 14% (2/14) |
| Pearson r between splits (over all 264 variant cells) | +0.272 | +0.694 |
| **Spearman ρ on global variant ranking** | **+0.843** | **+0.903** |
| Retention of train-best on test (r_train_pick / r_test_best) | 53% | 73% |

**Headline:** the *global ranking* of which SNR variants correlate with
DA is **highly stable across seed splits** (Spearman ρ = +0.84 for
DA-size, +0.90 for DA-ckpt). The dispersion cluster is consistently on
top in both pools.

The *exact* best variant per language does **not** generalize — only
1/14 languages keep the same pick under both seed pools, and even
folded into broader mathematical families the agreement is just 2/14.
But picking any dispersion-cluster member retains 73% of the optimal
DA-ckpt correlation on the held-out seed, so the family-level pick is
the part to trust.

**Recommendation:** treat `quartile_deviation` (or any dispersion
member) as the **portable global default**. Per-language tuning
that promises a stronger correlation than the dispersion-family
baseline does not generalize across the seed splits we tested and
should be treated as overfitting.

![Per-(language, variant) Pearson r — train vs test split](seeds_28_1797__vs__seeds_1904/variant_r_train_vs_test.png)

The DA-ckpt cluster lies tightly along the diagonal (slope ≈ 1); the
DA-size cluster has a much weaker correlation — DA-size is more
sensitive to the specific seed pool, DA-ckpt is more portable.

Three observations:
1. **`discrepancy` is the largest family in both splits.** It claims
   3–5 of the 12 covered languages no matter which seed pool you use,

   default.
2. **`depth` always wins for Thai but flips variant** (`tukey` on
   train, `projection` on test). The depth family makes sense for one
   specific language; the within-family choice is seed-dependent.
3. **No typological clustering** — the dispersion winners span Indo-European
   (eu, hi, sw) and Sinitic (zh), and the discrepancy winners span Romance
   (es), Slavic (ru), Semitic (ar) and Basque (eu). Best-variant choice
   isn't tracking language family.

## Key insights — updated

- **The dispersion family is the portable global default.**
  `quartile_deviation` / `aad` / `mpd` / `rms_deviation` / `dispersion`
  / `range` tie within ~0.02 at mean r ≈ 0.30 across the 12 languages,
  and that ranking holds on the held-out seed (Spearman ρ on the
  global variant ranking = **+0.84 DA-size, +0.90 DA-ckpt**; pooled
  per-cell Pearson r = +0.27 / +0.69).
- **Per-language tuning does not generalize across seed splits.**
  Only 1/14 (7%) of languages keep the same best variant; only 2/14
  (14%) keep the same family. Picking the train-best variant retains
  53% of the optimal r on DA-size and 73% on DA-ckpt — useful but
  noticeably degraded.
- **DA-ckpt is more transferable than DA-size.** Within-size early-vs-
  late ckpt ranking is less seed-sensitive than cross-size ranking.
  When evaluating new benchmarks, DA-ckpt picks transfer better.
- **The `(mix, seed)` model unit doubles the signal pool.** With 6
  model units per size (vs 3 under the single-seed Apertus baseline),
  per-language Pearson r values jump 2–3× and the dispersion-cluster
  variants cleanly separate from the others (instead of all sitting
  near +0.27).
- **Algebraic redundancy is unchanged.** The dispersion block
  correlates at r ≥ 0.999 across variants; relative-spread block
  (`iqr`, `rel_dispersion`, `rel_mpd`, `rel_std`) at r ≥ 0.998;
  `{discrepancy, star_discrepancy}` at r = 0.959.
- **Depth variants are still mostly useless.** `tukey` and
  `projection` correlate ~0 with DA on the train pool (r = 0.009 and
  -0.025), confirming the earlier finding that half-space depth
  doesn't work at small n.
- **`rel_std_snr` is no longer degenerate** (since the data_noise fix
  documented in CLAUDE.md). Sits in the relative-spread cluster.
- **Languages with sparse coverage are still skipped** — `de`, `fr`
  have ≤4 valid (task, size) cells on either pool.

## How to reproduce

```bash
# Variants CSV — one per seed pool
python multilingual/run_apertus_snr_variants.py --seeds 28,1797
python multilingual/run_apertus_snr_variants.py --seeds 1904
python multilingual/run_apertus_snr_variants.py --seeds 28,1797,1904

# Plots from each CSV
for pool in seeds_28_1797 seeds_1904 seeds_28_1797_1904; do
    python multilingual/analyze_snr_variants.py --out-dir results/snr_definition/$pool
    python multilingual/snr_definition_postprocess.py --out-dir results/snr_definition/$pool
done

# Train/test framework generalization
python multilingual/compare_seed_splits.py \
    --train-dir results/snr_definition/seeds_28_1797 \
    --test-dir  results/snr_definition/seeds_1904
```
