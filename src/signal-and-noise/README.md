### Signal and Noise: A Framework for Reducing Uncertainty in Language Model Evaluation

> Local fork of [allenai/signal-and-noise](https://github.com/allenai/signal-and-noise),
> extended to run the SNR / decision-accuracy framework on our multilingual
> pretraining ladders: first the 36-model sweep (4 sizes × 3 data mixtures ×
> 3 seeds, 12 languages), now the **predictivity ladder** (90M–1.7B × 7
> language settings × deep/shallow × data scheme A/B × seeds, 100 languages).

For the framework itself — the definitions of signal, noise, decision
accuracy, scaling-law error, and the AllenAI DataDecide / OLMo experiments —
see the original paper (Heineman et al., 2025,
[arXiv 2508.13144](https://arxiv.org/abs/2508.13144)). This README documents
what we use in this project; [CLAUDE.md](CLAUDE.md) is the back-of-house memo.

## Input: the ladder report

The source of truth for the predictivity analyses is the wide table
`ladder_report.csv` that [`src/pretrain/ladder_report.py`](../pretrain/ladder_report.py)
builds from disk (training logs, harness results, `score_bpb.py` output) and
publishes to the HF dataset `msnr-data/ladder-report`
(`configs/hf_wandb.json` → `repo_id_ladder_report`). One row per checkpoint,
one column per measurement: `bench__<task>`, `bpb__<subset>`, `ppl__<subset>`,
`macro_bpb`, `loss`, `run__<metric>`.

[`snr/download/ladder.py`](snr/download/ladder.py) downloads it on first use
(or reads `$SNR_LADDER_DIR`) and melts it into the long schema every script
consumes — one row per (model, step, task) — with the ladder's axes as columns
(`size`, `L`, `arch`, `scheme`, `seed`) and per-language BPB as tasks of its
own (`bpb_rus_Cyrl`, `bpb_dclm`, `bpb_macro`). Diverged and unfinished runs
are dropped, and checkpoints are restricted to the grid every size shares
(k/10 for benchmarks, k/20 for BPB) so late-window noise spans the same
fraction of training at every size.

The 36-sweep and the external reference models still load from the
`multilingual-snr/multilingual-snr-eval-results` parquet
([`snr/download/apertus.py`](snr/download/apertus.py)); which loader a pool
uses is declared per `source` in `configs/models.json` (`loader: ladder`).

## Pools

| pool | models | use |
|---|---|---|
| `predictivity` | one run per (size, L, arch, scheme), seed 1904 | the headline pool: every README's numbers |
| `predictivity_seeds` | every trained cell, all seeds | seed-noise estimates (rq03, rq05) |
| `predictivity_seeds_train` / `_test` | the ×3 cells split by seed (64/313 vs 1904) | the seed holdout of rq03 |
| `predictivity_all` | every trained cell, all seeds and all five schemes | rq01, rq03, rq05 and rq06: one intervention at a time against its own baseline |
| `seeds_*`, `custom_swissai_hf`, `external` | the 36-sweep and the external models | committed history; still runnable |

The size axis (`snr` section of `configs/models.json`): proxies 90M–600M,
target 1B, 1.7B enters through the cross-size DA pairs; ckpt-DA reads early
checkpoints at 20/40/60/80 % of each run (1×C … 4×C); late-window noise over
the last 5 checkpoints.

## Run everything

```sh
pip install -e .                      # or the deps in pyproject.toml
bash run_all_predictivity.sh          # downloads the ladder report, runs rq00–rq09, writes the READMEs' auto blocks
SNR_LADDER_DIR=/path/with/ladder_report.csv bash run_all_predictivity.sh   # a local copy (capstor, a fixture)

The per-task DA and SNR tables are cached per pool and reused, but only while
they are newer than `ladder_report.csv`. A refreshed report invalidates them, so
re-running after new evals land recomputes everything downstream instead of
quietly reporting last night's numbers.
```

`run_all_pretraining.sh` is the 36-sweep driver (parquet pools).

## Research questions

One directory per question under [`analysis/`](analysis/), each read
results-first (README: question · setup · methodology · results, the results
blocks regenerated by the script). Four themes: **A**, is the evaluation
predictable; **B**, can it be measured cheaply; **C**, does the framework
generalise; **D**, can the benchmarks be improved:

| RQ | directory | theme | question |
|---|---|---|---|
| RQ0 | [`rq00_gate_and_curves/`](analysis/rq00_gate_and_curves/) | A | Which benchmarks clear chance at each size (the gate every RQ applies), and how scores move with compute and along the run |
| RQ1 | [`rq01_scaling_predictability/`](analysis/rq01_scaling_predictability/) | A | What moves with size in a way a power law captures, and how well a fit on the proxy rungs predicts the reference (paper RQ1) |
| RQ2 | [`rq02_decision_accuracy/`](analysis/rq02_decision_accuracy/) | A | Does a benchmark rank the design variants at a small size, or an early checkpoint, the way the reference does? |
| RQ3 | [`rq03_noise_and_snr/`](analysis/rq03_noise_and_snr/) | B | Seed vs checkpoint noise, the effect of a design decision against it, the 22 SNR definitions per task, the seed holdout |
| RQ4 | [`rq04_surrogates/`](analysis/rq04_surrogates/) | B | Which cheap statistic — an SNR definition, its parts, early agreement, fit quality, margin above chance — predicts decision accuracy (paper RQ3) |
| RQ5 | [`rq05_design_decisions/`](analysis/rq05_design_decisions/) | C | Which proxy sizes, and how early in their run, rank the five design decisions like the reference at each L (paper RQ2, RQ4) |
| RQ6 | [`rq06_language_transfer/`](analysis/rq06_language_transfer/) | C | Does per-language scaling transfer to unmeasured and never-trained languages? (paper RQ5) |
| RQ7 | [`rq07_external_frameworks/`](analysis/rq07_external_frameworks/) | C | Do our SNR values agree with AllenAI DataDecide on the shared English tasks? |
| RQ8 | [`rq08_subset_selection/`](analysis/rq08_subset_selection/) | D | Can a language or subject subset of a benchmark beat the full set's SNR, beyond a random-subset null? |
| RQ9 | [`rq09_benchmark_design/`](analysis/rq09_benchmark_design/) | D | Which design features (curation, format, option count, length) predict a benchmark's SNR? |

The paper's five questions map to rq01 (RQ1), rq05 (RQ2, RQ4), rq04 (RQ3)
and rq06 (RQ5). Publication
figures: [`analysis/report_figures/make_figures.py`](analysis/report_figures/make_figures.py)
for fig1–fig4; the RQ figures are written by their RQ scripts and copied into
`documents/paper/figures/` by `documents/paper/figures/make_rq_figures.py`.
Every figure script imports the palette from [`analysis/style.py`](analysis/style.py).

## Calculating SNR

Given scores from a population of models (`signal_scores`) and intermediate
checkpoints (`noise_scores`):

```python
import numpy as np

def signal_to_noise_ratio(signal_scores: np.ndarray, noise_scores: np.ndarray) -> float:
    """
    signal = \\max_{j,k} |m_j - m_k| / m̄
    noise = σ_m / m̄
    snr = signal / noise
    """
    dispersion = np.max([np.abs(mj - mk) for mj in signal_scores for mk in signal_scores])
    signal = dispersion / np.mean(signal_scores)
    noise = np.std(noise_scores) / np.mean(noise_scores)
    return signal / noise
```

The 22 variants of this definition live in [`snr/snr_variants.py`](snr/snr_variants.py).
`noise_scores` is whatever counts as "the same model measured again": the late
checkpoints of one run (rq03) or the final scores of seed replicates (rq03, rq05).

Decision accuracy is `snr.metrics.decision_acc_fast`, upstream's kernel with
one documented change: ties are compared by sign, so the value no longer
depends on the order the models are listed in (upstream's kernel is kept as
`decision_acc_fast_upstream`; the effect is quantified in
[`rq02_decision_accuracy/README.md`](analysis/rq02_decision_accuracy/README.md)).
`tests/` pins both: `python -m unittest discover -s tests`.
